# Developer overview

The five-minute orientation. For depth, go to **[docs/wiki/Home.md](wiki/Home.md)**.

## What is this?

**EARTH** is a native Android idle/incremental game: build a civilization, produce greenhouse
gases, heat the planet past habitability, reset, repeat faster. Kotlin and Jetpack Compose, no
WebView and no cross-platform runtime.

It began as a TypeScript/React game shipped through Capacitor. The Android app is a full native
rewrite, and the original engine is kept as a **parity oracle** — the port's correctness was
established by executing the reference and comparing answers, not by reading the diff.

│   ├── proguard-rules.pro
│   └── src/
│       ├── main/java/com/earthgame/idle/

### Where is the game engine?

**`app/src/main/java/com/earthgame/idle/domain/`** — and it has no Android dependency at all. Its
only non-project imports are `java.math`, `kotlin.math`, `kotlin.random` and
`kotlinx.serialization.json`.

| Want to change… | Look at |
| :-- | :-- |
| How a tick works | `engine/Simulation.kt` — `simulateStep(state, dt)` |
| Absences, events, achievements, purchases, prestige | `engine/GameLoop.kt` |
| Numbers that exceed `Double` | `engine/GameDecimal.kt` |
| Balance / pacing | `engine/Constants.kt` and `technologies/Scaling.kt` |
| The technology tree | `technologies/*Technologies.kt` (11 branch files) |
| Climate maths | `climate/Climate.kt`, `climate/Habitability.kt`, `model/Gases.kt` |
| Prices and buying | `economy/Economy.kt`, `technologies/TechnologyRegistry.kt` |
| Content | `achievements/`, `challenges/`, `events/`, `milestones/` |
| What a playthrough *is* | `model/GameState.kt` |

### Where is persistence?

`data/repository/SaveRepository.kt` is the interface (no Android types, so tests drive a real
save/load in memory). `data/persistence/DataStoreSaveRepository.kt` is the only implementation.
The format and migrations live in `domain/save/`.

On a device: `/data/data/com.earthgame.idle/files/datastore/earth-save.preferences_pb`.

### Where is Android-specific code?

`platform/` (haptics, audio, ads), `presentation/` (ViewModel + Compose), and the two entry points
`MainActivity.kt` and `EarthApplication.kt`. That is all of it.

### Where are the tests and the fixtures?

`app/src/test/` for the 220 JVM tests, `app/src/androidTest/` for instrumented ones. The golden
parity fixtures are `app/src/test/resources/parity/*.json`, generated by
`tools/ts-reference/exportParityFixtures.ts` and **committed**, so the test suite needs no Node.

## Build and test

```bash
./gradlew test                    # 220 JVM tests, seconds
./gradlew lintDebug lintRelease   # zero issues expected
./gradlew assembleDebug           # app/build/outputs/apk/debug/app-debug.apk
./gradlew bundleRelease           # app/build/outputs/bundle/release/app-release.aab
./gradlew connectedAndroidTest    # needs a device or emulator
```

Needs **JDK 21** and an Android SDK with `platforms;android-37` + `build-tools;37.0.0`, located via
`ANDROID_HOME` or `local.properties`. See [Build system](wiki/Build-System.md).

## The five things to know

**1. `domain/` has no Android in it.** That is what lets the whole simulation be tested on the JVM
in seconds, and it is the rule most likely to be broken by accident.
→ [Architecture](wiki/Architecture.md)

**2. `simulateStep(state, dt)` is pure, deterministic and step-size independent.** One call with
`dt = 8h` equals 115,200 calls with `dt = 250ms`, because the gas integration is closed-form. That
property is why offline progress is one calculation and there is no background service anywhere.
→ [Simulation](wiki/Simulation.md), [Offline progression](wiki/Offline-Progression.md)

**3. Every gameplay number is a `GameDecimal`, not a `Double`.** A finished run passes 10⁴⁰⁰. Using
a `Double` for anything a player accumulates makes it `Infinity` and `NaN`s everything downstream.
→ [GameDecimal](wiki/GameDecimal.md)

**4. `tools/ts-reference/` is the parity oracle.** Change gameplay maths in Kotlin and you change it
there too, regenerate the fixtures, and let the parity tests compare.
→ [Reference parity](wiki/Reference-Parity.md)

**5. Two threads produce state.** The tick runs on `Dispatchers.Default`; player actions come from
the main thread. Every transition is a read-compute-write under `stateLock`, never a bare
`MutableStateFlow.update`.
→ [UI architecture](wiki/UI-Architecture.md#threading)

## Where to start if you are changing gameplay

1. Read [Architecture](wiki/Architecture.md) and
   [Reference parity](wiki/Reference-Parity.md) — twenty minutes, and they save you a wasted PR.
2. Find the constant or data file. Almost everything is data:
   [`Constants.kt`](wiki/Economy-and-Production.md#the-balance-curves) for pacing,
   `technologies/*.kt` for content, `climate/` for the model.
3. Mirror the change in `tools/ts-reference/engine/`.
4. `cd tools/ts-reference && npx vitest run && npm run fixtures`
5. `./gradlew test`, then check `git diff --stat app/src/test/resources/parity/` shows only what you
   expected.
6. Update the affected wiki page.

Full procedure, and the specific things that go wrong: [Contributing](wiki/Contributing.md).
